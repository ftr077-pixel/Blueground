# Постоянный адрес для VoiceBridge

Пока идёт разработка, `make dev` поднимает сервер с временным туннелем —
его адрес меняется при каждом перезапуске, и поле в Twilio приходится
переписывать. Это установка на бокс, где уже крутится дашборд: адрес
становится постоянным и вписывается в Twilio один раз.

## Что нужно

- Ubuntu-бокс с уже настроенным Caddy (тот же, что в корневом `deploy/`)
- Поддомен, например `voice.твой-домен.com`, с DNS A-записью на IP бокса
- Заполненный `.env` (ключи те же, что на ноутбуке)

## Установка

На боксе, под root:

```bash
cd /opt/blueground && git pull
cp ~/voicebridge.env /opt/blueground/voicebridge/.env   # или заполнить на месте
bash /opt/blueground/voicebridge/deploy/install.sh
```

Скрипт поставит зависимости, проверит конфигурацию, зарегистрирует службу
и напечатает оставшиеся шаги — блок для Caddy и адрес для Twilio.

## Дальше

| Задача | Команда |
|---|---|
| Обновить код | `cd /opt/blueground && git pull && systemctl restart voicebridge` |
| Посмотреть события звонка | `journalctl -u voicebridge -f` |
| Проверить, что сервер жив | `curl -s localhost:8080/health` |
| Разбор последнего звонка | открыть `https://voice.твой-домен.com/debug/last-call` |

## Про логин

Консоль оператора, отладочная страница и её WebSocket закрыты паролем в
Caddy. Вебхук Twilio и медиа-сокет — нет: Twilio не умеет проходить
basic-auth. Это нормально для M0; настоящая аутентификация звонков —
проверка подписи Twilio — относится к M2 вместе с остальным control plane.
