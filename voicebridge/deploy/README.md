# Постоянный адрес для VoiceBridge

Пока идёт разработка, `make dev` поднимает сервер с временным туннелем —
его адрес меняется при каждом перезапуске, и поле в Twilio приходится
переписывать. Здесь — установка на бокс, где адрес становится постоянным
и вписывается в Twilio один раз.

Путь на боксе: **`/root/Blueground/voicebridge`**. Служба: `voicebridge`.

## Скрипты

| Файл | Что делает |
|---|---|
| `install.sh` | ставит зависимости, проверяет конфигурацию, регистрирует systemd-службу |
| `use-domain.sh` | переводит всё на твой домен: `.env`, Caddy, сертификат, рестарт |
| `install-caddy.sh` | только Caddy и сертификат (вызывается из `use-domain.sh`) |
| `install-autodeploy.sh` | таймер, который сам подтягивает `main` раз в минуту |
| `deploy.sh` | подтянуть `main` и перезапустить, дождавшись конца звонка |
| `autodeploy.sh` | один тик таймера: если `main` сдвинулся — вызвать `deploy.sh` |
| `install-ngrok.sh` | запасной путь, когда домена нет (см. `ngrok.md`) |
| `HANDOFF-domain.md` | пошаговый бриф на перевод под домен, для агента с доступом к боксу |

## Установка с нуля

```bash
cd /root/Blueground && git pull
cd voicebridge
cp .env.example .env      # заполнить ключи, проверить: make check-env
sudo bash deploy/install.sh
```

## Свой домен

Сначала A-запись поддомена на IP бокса, потом одна команда:

```bash
sudo bash deploy/use-domain.sh voice.твой-домен.com
```

Пропишет `VOICE_DOMAIN` и `PUBLIC_HOST`, поставит Caddy, получит сертификат,
перезапустит службу и напечатает две строки — для вебхука Twilio и для
redirect URI в Google Cloud. Обе консоли за твоим логином, туда вставляешь сам.

Скрипт откажется работать, пока DNS не указывает на этот бокс: раньше
сертификат всё равно не выдадут.

## Автообновление

```bash
sudo bash deploy/install-autodeploy.sh
```

После этого мерджа в `main` достаточно — бокс подтянет изменения сам в
течение минуты и перезапустится, дождавшись, пока закончится текущий звонок
(`/health` отдаёт `calls_active`). Выключить:
`systemctl disable --now voicebridge-update.timer`.

Таймер работает только с веткой `main`. Если переключиться на другую ветку
вручную, он отойдёт в сторону и ничего не перезапишет.

## Дальше

| Задача | Команда |
|---|---|
| Обновить код руками | `cd /root/Blueground/voicebridge && make deploy` |
| Посмотреть события звонка | `journalctl -u voicebridge -f` |
| Посмотреть автодеплой | `journalctl -u voicebridge-update -f` |
| Проверить, что сервер жив | `curl -s localhost:8080/health` |
| Проверить конфигурацию | `make check-env` (значения не печатает) |
| Проверить вендоров | `make preflight` |
| Разбор последнего звонка | `https://voice.твой-домен.com/debug/last-call` |

## Про логин

Консоль оператора, `/call` и `/debug/*` закрыты входом через Google
(SPEC A8) — настраивается в `.env`: `GOOGLE_CLIENT_ID`,
`GOOGLE_CLIENT_SECRET`, `OPERATOR_EMAILS`. Пустой `OPERATOR_EMAILS` не
пускает никого. Если Google не настроен, консоль остаётся открытой и служба
громко пишет об этом в журнал при старте.

Вебхук Twilio и медиа-сокет закрывать нельзя: Twilio не умеет проходить
логин, и любая авторизация на них кладёт все звонки. Что там остаётся
незакрытым — проверка подписи Twilio, и это работа M2.

`basic_auth` из `Caddyfile.snippet` — предыдущий вариант, до появления
входа через Google. Оставлен как запасной для бокса без OAuth.
